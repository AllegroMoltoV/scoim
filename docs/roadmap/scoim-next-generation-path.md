# 次の生成経路へ接続する差分

現在有効な仕様と処理順は、[SCoIM生成工程](../design/scoim-generation-workflow.md)を正本とします。この文書は、正本に対して実装がまだ追いついていない箇所だけを示します。

## 試聴用成果物をリリース単体で再現できるようにする

`v0.1.0`の試聴用SMFはハッシュで同一性を確認できます。ただし、Git管理から除外された入力と診断手順を使っているため、リリースに含まれるファイルだけでは同じSMFを再生成できません。

公開CLIから作った`v2`生成試行bundleを、モデルなしで同じMusicXMLとSMFへ再生できることは確認済みです。次は、版管理された固定bundleを配布物へ含め、新規環境でも同じ検査が通るようにします。参照曲の原本、認証情報、ローカル環境の絶対パスはbundleへ含めません。

この項目は、新規環境へリリース成果物だけを配置し、生成試行bundleから試聴用MusicXMLとSMFを再構築して、保存済みの出力とハッシュが一致したときに完了とします。

## 既知の品質課題を生成責務へ戻す

現時点の診断SMFでは、終止音と左手伴奏の厚みに改善余地があります。

これらを最終出力への場当たり的な加工で補わず、原因を所有する生成段階または変換段階へ割り当てます。

品質課題は、新しい生成経路を一度公開CLIへ接続したあと、生成を繰り返しても同じ問題が再現するかを確認してから個別に扱います。現在の設計へ未検証の解決方法は追加しません。

## 視覚的な共同編集

将来は、楽曲台本の構造、繰り返し、変奏、遷移を視覚的に編集できるGUIを検討します。初版では、JSONとCLIによる共同編集を維持します。

GUIの技術選定と詳細設計は、公開CLIの生成経路が安定し、利用者が実際に編集する情報の範囲が分かるまで行いません。
