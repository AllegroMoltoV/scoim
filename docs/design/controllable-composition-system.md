# 3分ピアノ生成プロファイル

`solo_piano_3m_v2`は、新しい対象関係を約3分の独奏ピアノで実証する[生成プロファイル](glossary.md#生成プロファイル)である。目的は、一曲を局所的に磨き続けることではなく、参照曲の特徴を使った新規生成、少数の制御、楽譜と演奏の分離、再現可能な記録が一つの流れとして成立するか確かめることにある。この生成プロファイルの制約を、音楽一般やSCoIM中核の恒久的な制約へ広げない。設計に対する実装の未完了箇所は[roadmap](../roadmap/scoim-next-generation-path.md)に記載する。

公開CLIの新規生成は`solo_piano_3m_v2`を既定値とする。`solo_piano_3m_v1`は明示指定する互換経路として残し、二つの型とbundleを相互に読み替えない。生成試行bundleの通信なし再生はmanifestの版に従う。

## ゴール

1. 約3分の独奏ピアノ曲を、壊れていないMusicXMLと演奏SMFとして生成する。
2. 選んだ参照曲または参照曲群の特徴へ、音符を複製せずに近づける。
3. 検証に合格した少数の生成制御を、同じ入口から指定できるようにする。
4. 入力、LLM応答、検査、修正、成果物の関係を後から再検証できるようにする。

## 成功条件

成功は一つの総合点へまとめない。

| 観点 | 成功の意味 |
|---|---|
| 形式と安全 | MusicXMLとSMFを再読込みでき、音符、ペダル、総尺、hashが整合する |
| 楽曲としての成立 | 約3分を通して和声、伴奏、構成、終止、演奏が繰り返し破綻しない |
| 参照との関係 | 定義済み特徴では近く、コピー検査に合格する。聴感未確認ならその限界を明記する |
| 制御 | 対象の性質が意図方向へ動き、別の性質や品質だけで差を説明しなくてよい |
| 再現性 | 使用した入力、モデル、実装、検査、成果物を一つの試行として追跡できる |

自動検査は探索を速くするために使い、人間の聴感と同じものとは扱わない。人間の試聴は、楽曲台本の承認、最終SMFの採否、制御名の知覚上の意味を初めて確かめる節目に使う。

## 初版の範囲

- 一人による独奏ピアノ
- 希望演奏時間は約180秒
- 上声と下声を持つピアノ書法
- 任意深度の構成木、再現、変奏、対比、回帰、遷移
- 一つの子区分を持たない区分で、[前景](glossary.md#前景)と伴奏など複数のマテリアル配置を併用する楽譜生成単位
- MusicXMLを楽譜、SMFを演奏として別々に出力
- フレーズと局所和声を考慮したペダル
- 参照曲を基準にした新規生成
- 候補名としての`あかるさ`、`高さ`、`発音頻度`

3制御はすべて公開済みではない。名称とコーパス上の観測方法を定めた段階であり、生成対照に合格した項目だけを公開する。詳しくは[生成制御](generation-control-interface.md)を正本とする。現行の制御設計は`v1`を対象としており、`v2`には接続されていない。

## `v2`の生成能力

`solo_piano_3m_v2`の型付き能力は次のとおりとする。

- 編成は`solo_piano`である。
- 希望演奏時間は180秒である。
- マテリアル配置の役割として`foreground`と`accompaniment`を扱う。
- 一つの子区分を持たない区分に一つ以上のマテリアル配置を許し、固定の最大数を設けない。各配置の音符は区分内の異なる位置で始まり、終わってよい。
- 区分を対象にした演奏指示を扱う。
- マテリアル配置を対象にした演奏指示は扱わない。
- [演奏要素](glossary.md#演奏要素)として`timing`、`dynamics`、`articulation`、`coordination`、`pedal`を扱う。
- [演奏指示](glossary.md#演奏指示)から選ぶ演奏方法を、[演奏選択語彙](glossary.md#演奏選択語彙)に含まれる値へ制限する。
- [強弱方針](glossary.md#強弱方針)は、前景と伴奏を声部から推測しない`legacy-unison-v1`だけを扱う。配置単位の強弱補正が必要な強弱方針は扱わない。
- 明示的な変奏関係は、伴奏または遷移専用として使うマテリアル配置を元または先に含まない場合だけ、フェーズ4・5で実現できる。伴奏として使うマテリアルも、明示的な変奏関係の元または先に含めない。
- マテリアル配置遷移は、元、遷移専用、先の三つがすべて`foreground`であり、遷移専用配置が他の配置を持たない専用区分にある場合だけ、フェーズ4・5で実現できる。構造提案が明示した遷移専用区分からPythonが有効な候補を作り、関係提案はその候補を選ぶ。
- 伴奏で同じマテリアルを再利用する場合は、明示的な変奏関係を作らず、フェーズ5が直前の同一マテリアル配置を比較元とする。

非対応の対象、演奏要素、変奏、遷移を別の対象や要素へ読み替えず、非対応の強弱方針を旧レンダラーの`foreground_voice`へ読み替えない。編成または時間が合わない場合は`unsupported_profile`、表現は正しいが能力外の場合は`unrepresentable`とする。

## プロファイル内の責務

```text
検証済み楽曲設計データ
        ↓
参照特徴と制御要求を生成目標へ解決
        ↓
フェーズ3: PiecePlanと共有和声
        ↓
フェーズ4・5: 前景と伴奏
        ↓
フェーズ6: ScoreSpec
        ↓
フェーズ7: PerformanceSpecとRenderedPerformance
        ↓
フェーズ8: MusicXMLと演奏SMF
```

フェーズ7は、自然言語の演奏指示を有限な演奏方法へ変換する。知覚上の達成は自動で合格にせず、`unverified`として記録する。フェーズ8はLLMを呼ばず、検査済み楽譜と演奏から最終成果物を作る。設計に対する実装の未完了箇所は[roadmap](../roadmap/scoim-next-generation-path.md)に記載する。

データと変換の詳細は[ピアノ生成の全体像](performance-generation-pipeline.md)、実行の順序と修正は[SCoIM生成工程](scoim-generation-workflow.md)に置く。

## 利用者が変えられる候補

- 参照曲または参照曲を自動選択する指定
- 検証に合格した`あかるさ`
- 検証に合格した`高さ`
- 検証に合格した`発音頻度`

尺、区分数、マテリアル数、ペダル保持率、上下声の同期率、候補数、修正回数、LLMモデルは通常の音楽パラメータにしない。異なる用途は、多数のノブを追加するのではなく、将来の別の生成プロファイルとして扱う。

## 参照と制御の考え方

参照曲の特徴は、奏法とテクスチャ、リズムと時間、音高と和声語彙などを分けて扱う。低次元の一つの距離だけで作風や品質を決めない。参照曲固有の長期構成は現行の分析で信頼できる正解を得られていないため、初版の類似目標には含めない。

利用者向け制御は数学的に独立しているとは仮定しない。主に変えたい性質と、一緒に変わった性質を分けて記録する。外れ値、和音水増し、全体BPMの変更、単純移調だけで数値を達成した候補は、品質と副作用を別途検査する。

## 非ゴール

- 参照曲の音符列を複製すること。
- 「似ている」「良い曲」を一つのlossだけで決めること。
- 初版から任意の編成、尺、ジャンルを扱うこと。
- 3項目すべてを検証前に公開すること。
- 232曲だけで専用モデルを学習すること。
- GUI、複数LLMのアンサンブル、汎用プロバイダー基盤を同時に作ること。

## 設計を見直す条件

- 別の参照曲でも同じ基準曲や同じ構成しか生成できない。
- 参照特徴が無害な変換と音楽を壊す変換を区別できない。
- 制御の主効果が動かず、別の性質の変化だけで差が生まれる。
- 到達不能な要求を達成済みとして返す。
- 内容修正が承認済みの構造や無関係なマテリアルを変える。
- 自動評価と人間の節目評価が複数例で繰り返し逆転する。
- 一つの局所品質を詰め続け、全工程を再び通せない。

この生成プロファイルに関する設計判断の状態は[決定状態](scoim-decision-status.md)に従う。
